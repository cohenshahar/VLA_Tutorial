### 1. Session 2 Optimizations

#### PD Position Hold (Part A & B)
When no key is pressed the arm now freezes at its last position using a PD controller instead of going limp.

**Part A:**
```python
hold_qpos_a = np.zeros(2)
KP_A, KD_A = 2.5, 0.4

# When key released:
ctrl[i] = np.clip(KP_A*(hold_qpos_a[i] - qpos[i]) - KD_A*qvel[i], -1, 1)
# When key pressed: update hold target
hold_qpos_a[i] = data_a.qpos[i]
```

**Part B (3DOF):** Same pattern across all 3 joints. Hold target also resets on Space/Enter.

**Why it matters:** Without hold, the arm drifts under gravity every time you release a key — makes precise control impossible.

### 2. Key Conflict Fixes

MuJoCo's viewer intercepts certain keys at the GLFW level — they **cannot** be blocked. These conflicts were all hit during testing:

| Key | MuJoCo viewer action | Our use | Fix |
|-----|---------------------|---------|-----|
| `A` | Axis toggle | Shoulder left | → remapped to `←` |
| `D` | Depth visualization | Shoulder right | → remapped to `→` |
| `E` | Edge toggle | Wrist up | → remapped to `PgUp` |
| `W` | Wireframe | (unused but dangerous) | → avoided |
| `S` | Shadow toggle | (unused) | → avoided |
| `Space` | Pause/unpause sim | Reset | → remapped to `Enter` |

**Final control layout (Parts A & B):**

| Key | Action |
|-----|--------|
| `←` / `→` | j1 — shoulder yaw |
| `↑` / `↓` | j2 — elbow pitch |
| `PgUp` / `PgDn` | j3 — wrist (Part B only) |
| `Enter` | Reset |
| `Q` | Next part |
| `1/2/3` | Print joint angles + fingertip pos (Part B) |

#### Red Ball Unreachable Bug
The arm's fingertip was moving in the z=0.09 plane but the target ball was placed at z=0.05. The z-gap alone was larger than the touch threshold.

**Fix:**
```xml
<!-- Before -->
<body name="target" pos="0.3 0.1 0.05">
<!-- After -->
<body name="target" pos="0.3 0.1 0.09">
```
Touch threshold also raised from 0.04 → 0.05 m for a better feel.

---

#### Part C step_timer Bug
When switching between mode 2 (Step) and mode 3 (Random), both shared `step_timer[0]` without resetting it. Mode 3 could fire immediately or skip entirely depending on where the counter was.

**Fix:** Reset `step_timer[0] = 0` on every mode switch.

Also added a periodic mode reminder every 5 seconds so you always know what's running.

### 3. Session 3 — Motion Vocabulary

Ran the full 10-motion vocabulary session. One robot, keys 1–0, fully autonomous motions. Each motion prints its name, description, and the code principle on switch.

| Key | Motion | Primitive | Code idea |
|-----|--------|-----------|-----------|
| 1 | IDLE | Zero | `ctrl[:] = 0` |
| 2 | SWEEP HORIZONTAL | Sinusoidal | `sin(0.8*t)` on j1, PD hold j2+j3 |
| 3 | REACH FORWARD | PD | `targets = [0, 0, 0]` |
| 4 | REACH UP | PD | `targets = [0, -1.1, 0.3]` |
| 5 | REACH RED (IK) | Jacobian IK | `J† * error * 7.0` |
| 6 | REACH GREEN (IK) | Jacobian IK | same, different `tgt_pos` |
| 7 | DRAW CIRCLE | Sinusoidal | `sin(t)` + `sin(t + π/2)` |
| 8 | TREMOR | PD + noise | `ctrl += normal(0, 0.5)` |
| 9 | SLOW FALL | Damping only | `ctrl = -Kd * vel` |
| 0 | WAVE | Sinusoidal | `sin(4*t)` j1 + `sin(6*t)` j3 |

**The 4 control primitives everything reduces to:**
```
ZERO:       ctrl[i] = 0
PD:         ctrl[i] = Kp*(target - qpos[i]) - Kd*qvel[i]
SINUSOIDAL: ctrl[i] = A * sin(freq * t + phase)
IK:         ctrl    = J† * cartesian_error
```

## Key Physics Parameters Reference

| Parameter | Where | Effect |
|-----------|-------|--------|
| `gear` (XML actuator) | Model XML | Overall torque gain. 5=strong, 1=soft |
| `damping` (XML joint) | Model XML | How fast motion bleeds off |
| `TORQUE` / `TORQUE_B` | Python | Command magnitude per keypress |
| `timestep` | `<option>` | Sim step size (0.005s = 200 Hz) |
| `Kp` | PD control | Spring gain — how hard to push toward target |
| `Kd` | PD control | Damper gain — how hard to brake velocity |
| `freq` | sinusoidal | Cycles per second (rad/s). Higher = faster |
| `A` | sinusoidal | Amplitude. Higher = wider arc |

## Notes for Better Work Next Time

### MuJoCo Viewer Key Conflicts — Always Avoid
Never bind robot controls to these keys — MuJoCo GLFW intercepts them unconditionally:

```
A — axis overlay toggle
D — depth visualization
E — edge overlay toggle
W — wireframe toggle
S — shadow toggle
F — fullscreen
Space — pause / unpause simulation
H — help overlay
Tab — select body
```

**Safe keys for robot control:** Arrow keys, PgUp/PgDn, Enter, Z, X, C, V, B, N, M, Q (for quit)

---

### XML Site Tags Are Required for Distance Checks
Any body you want to measure distance to in Python **must have a `<site>` child**. Geoms do not expose position via `site_xpos`. Always add:
```xml
<body name="target">
  <geom .../>
  <site name="my_site" size="0.005"/>   ← required!
</body>
```
Then in Python: `data.site_xpos[mujoco.mj_name2id(model, mujoco.mjtObj.mjOBJ_SITE, "my_site")]`

---

### Z-Plane Alignment for 2D Arms
A horizontal 2D arm swings at the z-height of its base. Always place targets at the same z as the fingertip, not at ground level. Check with:
```python
print(data.site_xpos[ee_id])   # see where fingertip actually is
```

### PD Hold Pattern (Copy-Paste Template)
```python
hold_qpos = data.qpos.copy()
KP, KD = 2.5, 0.4

for i in range(n_joints):
    if key_pressed_for_joint_i:
        hold_qpos[i] = data.qpos[i]          # update hold target
    else:
        ctrl[i] = np.clip(
            KP*(hold_qpos[i] - data.qpos[i]) - KD*data.qvel[i],
            -1, 1
        )
```

### Jacobian IK Pattern (Copy-Paste Template)
```python
jac = np.zeros((3, model.nv))
mujoco.mj_jacSite(model, data, jac, None, ee_site_id)
jac_arm = jac[:, :model.nu]   # trim to actuated DOF only

error = target_pos - data.site_xpos[ee_site_id]
damping = 0.05
ctrl = jac_arm.T @ np.linalg.solve(
    jac_arm @ jac_arm.T + damping * np.eye(3),
    error * 7.0    # gain — increase for faster convergence
)
ctrl = np.clip(ctrl, -1, 1)
```
